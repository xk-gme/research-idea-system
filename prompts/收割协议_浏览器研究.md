# 收割协议：浏览器研究收割（形态一）

适用对象：拥有浏览器 / 网页搜索 / 网页阅读工具的 agent 会话（ZCode、Codex 等）。目标：在正式 `research` 运行前，自由检索并阅读网络文献，把**真实可核查的来源与摘录**收割成本地语料，作为文献上下文注入有界研究循环。本协议产出会进入复现证据链，**真实性要求高于全面性**。

## 工作流程

1. **以任务背景为纲**：读取收割工作目录下《收割指引.md》末尾附的任务背景全文。检索与摘录都必须围绕该任务的方法需求（不要泛泛收集领域新闻）。
2. **规划检索词**（自己想，5–10 个）：覆盖不同方法族，例如经典基线、最新 SOTA、评审/综述、失败教训、任务官方文档。中英文均可，检索建议英文。
3. **检索并选源**：每个检索词选 0–3 个高质量来源。优先级：同行评审论文与预印本 > 官方技术文档/模型 README > 高质量技术博客。整篇无法读到正文的来源不要收录。
4. **阅读并摘录**：每个来源摘 5–20 行**关键原文要点**（方法机制、约束、实证结论、与任务直接相关的数字）。摘录是给下游 LLM 看的文献块，用自己的话压缩可以，但**不得编造**原文没有的内容。
5. **落盘**：每个来源一个 `source_NN.md` 文件，格式见下。同时把条目追加进 `harvest_manifest.json`。
6. **数量**：5–15 条为宜。够用即止，不追多。

## source_NN.md 文件格式（严格遵守）

```markdown
---
url: https://arxiv.org/abs/xxxx.xxxxx        # 必填，真实可访问
title: Quantile regression for epidemic forecasts  # 必填
accessed_at: 2026-10-19T08:30:00Z            # 必填，实际访问时间(UTC)
agent: zcode-session                          # 执行收割的 agent 标识
tool: WebFetch                                # 使用的工具(WebSearch/WebFetch/browser)
---
（5–20 行关键摘录或忠实压缩的要点，面向下游 LLM 的文献块）
```

## harvest_manifest.json 格式

```json
[
  {"file": "source_01.md", "url": "https://...", "agent": "zcode-session", "tool": "WebFetch"},
  {"file": "source_02.md", "url": "https://...", "agent": "zcode-session", "tool": "WebSearch"}
]
```

## 硬性规则

1. **每个 URL 必须真实访问过**；禁止凭记忆写论文标题和结论。
2. front-matter 三字段（url/title/accessed_at）缺一不可，缺失的条目会让语料加载失败。
3. 同一 URL 只收一次（加载器会按 URL 去重，重复条目记为 skipped）。
4. 不改写任务背景，不产出想法——想法生成是下游 research 阶段的事，收割只提供文献。
5. 完成后把工作目录交回：`python -m idea_system.pipeline research --task <任务名> --corpus <harvest目录>`。

## 与证据链的关系

收割文件的 SHA256、条目清单（含被跳过的重复项）会记入 run 的 `manifest.json`（`corpus` 字段与 `corpus:*` 文件哈希）。收割来源在想法引用中编号为 C1、C2…，与 arXiv 检索来源（S 编号）并列，事后逐条可核查。
